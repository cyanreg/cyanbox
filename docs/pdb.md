# Writing Pioneer/AlphaTheta "Device Library" USB exports (export.pdb) from scratch

Implementation reference for a C writer. Everything is little-endian unless stated
otherwise (ANLZ files are big-endian). Offsets are hex, relative to the start of the
structure named in the section heading.

Status markers used throughout:

* **[HW]** behaviour confirmed on real players by the cited project/report.
* **[RB]** byte-for-byte what rekordbox writes, re-verified for this document by dumping real
  rekordbox exports (see "Reference files" below).
* **UNCERTAIN** sources disagree, or nobody has measured it. Both versions are given.

Compiled 2026-10-06.

## 1. USB directory layout

Sources: baken `lib.rs`, `layout.rs`, `settings.rs`, issue #115 ("Facts from real files");
rekordcrate `data/complete_export`; fourfour PIONEER.md §1, §7, §9; Deep Symmetry exports.html.

```
<volume root>/
├── Contents/<Artist>/<Album>/<file>            audio (path is free-form, see 1.2)
└── PIONEER/
    ├── rekordbox/
    │   ├── export.pdb          Device Library (DeviceSQL)                      <- this document
    │   ├── exportExt.pdb       Device Library extension (My Tag)  (§3)         optional
    │   ├── exportLibrary.db    OneLibrary (SQLCipher SQLite)                    other format
    │   ├── exportLibrary.db-wal / -shm                                          other format
    │   ├── export.pdb.bak      written BY THE PLAYER on first use
    │   └── RBFLTR.DAT          written BY THE PLAYER (model/firmware, filter)
    ├── USBANLZ/P<XXX>/<XXXXXXXX>/ANLZ000N.{DAT,EXT,2EX}   analysis (1.3)
    ├── Artwork/<NNNNN>/a<id>.jpg, a<id>_m.jpg            artwork (1.4)
    ├── MYSETTING.DAT  MYSETTING2.DAT  DJMMYSETTING.DAT  DEVSETTING.DAT   (settings; covered elsewhere)
    └── CDJ/  CDP/  LOG/  MPJ/  extracted/            written BY PLAYERS - never delete
```

* Settings files go in `PIONEER/`, **not** the volume root [RB] (rekordcrate `complete_export`, baken #115).
  Sizes 148/148/160/140 bytes (MYSETTING, MYSETTING2, DJMMYSETTING, DEVSETTING). All optional for
  the library to load (baken `--no-settings` sticks load) [HW]. Details are out of scope here.
* Players write `ANLZ0001.*` next to a rejected `ANLZ0000.*` when they re-analyse (fourfour §7) [HW].
* fragmede FORMAT.md says the folder is "sometimes `.PIONEER/`, hidden". **UNCERTAIN** (not seen in
  any file examined here); write `PIONEER`.
* On macOS-written FAT sticks, remove AppleDouble `._*` files under `PIONEER/` and `._Contents`,
  `._PIONEER` (baken does; fourfour recommends `dot_clean`). Effect on players: **UNCERTAIN**.

### 1.1 Files to remove when you replace the library

If you write only `export.pdb` onto a stick that rekordbox exported before, delete
`exportLibrary.db`, `exportLibrary.db-wal`, `exportLibrary.db-shm` and the old `exportExt.pdb`
**after** the new `export.pdb` is safely written (baken #208, commit 305d73d). Otherwise:
rekordbox reports "library inconsistency on the device"; OneLibrary players (CDJ-3000X, XDJ-AZ,
OPUS-QUAD, OMNIS-DUO) show the stale library; and CDJ-3000 fw 3.30 (withdrawn) preferred the
OneLibrary even when it was older or empty (MusicTech/AlphaTheta, §6). Never delete the
player-written files listed above.

### 1.2 `Contents/` layout

* rekordbox convention [RB]: `/Contents/<Artist>/<Album>/<file>`; `UnknownArtist` / `UnknownAlbum`
  when empty; trailing spaces trimmed; FAT-illegal characters → `_`; file **stem cut to 43
  characters** keeping the extension; collisions get `-1`, `-2` … (baken `layout.rs`, verified on
  587 tracks; rekordcrate demo export: `/Contents/UnknownArtist/UnknownAlbum/NOISE.wav`,
  `/Contents/Loopmasters/UnknownAlbum/Demo Track 1.mp3`).
* **The player does not care about the rule**, only that the track row's `file_path` names the
  file exactly (baken #115). Paths are absolute from the volume root, `/`-separated, starting with `/`.
* `file_path` is also the input of the ANLZ hash (1.3), so it must be byte-identical (in UTF-16
  code units) to what you hash.
* HFS+ stores names decomposed (NFD) while rekordbox stores NFC in the PDB. Whether players match
  them: **UNCERTAIN** (baken README, untested). FAT32 avoids the question.

### 1.3 `PIONEER/USBANLZ` path scheme

**Players ignore the PDB `analyze_path` string and compute the directory from `file_path`**
(fourfour §1, CDJ-3000 fw 3.19 [HW]; baken verified 586/587 paths of a rekordbox 7.2 export, the
587th being a hash collision, see below). Still write `analyze_path` = the computed path, as
rekordbox does (OneLibrary's `analysisDataFilePath` holds the same string).

Algorithm (fourfour notes, "use freely"; same constants in baken `anlz/hash.rs`, MIT):

```c
/* path: the track's file_path as UTF-16 code units, e.g. "/Contents/A/B/x.flac" (leading '/') */
uint32_t h = 0;
for (size_t i = 0; i < n_units; i++) {
    uint32_t c = units[i];           /* UTF-16 code unit, surrogates as two units */
    h = h * 0x5BC9u + c;             /* mod 2^32 */
    h = h * 0x93B5u + c;             /* mod 2^32 */
}
uint32_t r = h % 200003u;            /* 0x30D43 */
uint32_t p = (r & 0x01)              /* bit 0  -> 0 */
           | ((r >> 1)  & 0x02)      /* bit 2  -> 1 */
           | ((r >> 4)  & 0x04)      /* bit 6  -> 2 */
           | ((r >> 4)  & 0x08)      /* bit 7  -> 3 */
           | ((r >> 5)  & 0x10)      /* bit 9  -> 4 */
           | ((r >> 8)  & 0x20)      /* bit 13 -> 5 */
           | ((r >> 10) & 0x40);     /* bit 16 -> 6 */
sprintf(dir, "/PIONEER/USBANLZ/P%03X/%08X", p, r);   /* upper-case hex */
```

Test vectors [RB] (re-verified for this document against rekordbox's own `analyze_path` strings
in the rekordcrate demo export):

| file_path | directory |
|---|---|
| `/Contents/Loopmasters/UnknownAlbum/Demo Track 1.mp3` | `P016/0000875E` |
| `/Contents/Loopmasters/UnknownAlbum/Demo Track 2.mp3` | `P053/0001D21F` |
| `/Contents/UnknownArtist/UnknownAlbum/NOISE.wav` | `P019/00020AA9` |
| `/Contents/UnknownArtist/UnknownAlbum/SINEWAVE.wav` | `P043/00011517` |
| `/Contents/UnknownArtist/UnknownAlbum/SIREN.wav` | `P017/00009B77` |
| `/Contents/UnknownArtist/UnknownAlbum/HORN.wav` | `P021/00006D2B` |
| `/Contents/XamarA/UnknownAlbum/Unreal.mp3` (baken test) | `P060/00012938` |

(fourfour's third published vector, `/Contents/Huerta/Tatra Motokov - Huerta.flac` →
`P012/0000530C`, is reported wrong by baken #115.)

* **Collisions** (mod 200003, ≈ n²/400000 pairs): rekordbox gives the second track in export
  order `ANLZ0001.*` in the same directory and points its `analyze_path` there (baken #176, matched
  rekordbox's one collision in 587 tracks). The player identifies the right file by its `PPTH`.
* File names: `ANLZ%04u.DAT`, `.EXT`, `.2EX` (upper case).
* ANLZ gotchas that make players reject files (details belong to the ANLZ document):
  `PPTH` must be the USB-relative path in **UTF-16BE including a UTF-16 NUL terminator**,
  `len_path = (chars+1)*2`; without the NUL the CDJ-3000 rejects the file and writes its own
  `ANLZ0001.DAT` (fourfour §2 [HW]; [RB]: `PPTH len_path 104` for a 51-char path).
  CDJ-3000 re-analyses when `.EXT` is missing (fourfour [HW]). Section order seen [RB]:
  `.DAT`: PPTH PVBR PQTZ PWAV PWV2 PCOB PCOB; `.EXT`: PPTH PWV3 PCOB PCOB PCO2 PCO2 PQT2 PWV5 PWV4
  [PVB2] PSSI; `.2EX`: PPTH PWV7 PWV6 PWVC. PMAI header bytes 0x0C..0x1B [RB]:
  `00000001 00010000 00010000 00000000`. `PSSI` is XOR-masked on sticks (baken #115).

### 1.4 `PIONEER/Artwork`

* Row path [RB]: `/PIONEER/Artwork/%05u/a%u.jpg` with folder number **`id / 20 + 1`**
  (ids 1–19 → `00001`, 20–39 → `00002`, 100 → `00006`; verified on 1500 artwork rows of a real
  rekordbox 7 stick and the 7.2.18 export). Artwork ids start at 1.
* Sizes (Deep Symmetry exports.html): `a<id>.jpg` is **80×80**; recent rekordbox also writes
  `a<id>_m.jpg` at **240×240** (`_m` before the extension). JPEG only. rekordcrate PR #259 writes
  exactly those two sizes.
* UNCERTAIN: a CDJ-3000 tester (baken #116) said rekordbox writes "the extracted images in the three
  required sizes"; fourfour's OneLibrary schema comment shows `image.path` like
  `/PIONEER/Artwork/00001/b1.jpg`. A third size/prefix may belong to OneLibrary. Not verified.
* Artwork is optional: deleting `PIONEER/Artwork` from a rekordbox stick still loads on CDJs
  (Swiftb0y in rekordcrate PR #259 [HW]); baken writes `artwork_id = 0` and passed on CDJ-3000 and
  NXS2 [HW] (artwork simply not shown).

## 2. export.pdb (DeviceSQL)

Sources for the whole section: Kaitai `rekordbox_pdb.ksy`; Deep Symmetry exports.html; rekordcrate
`src/pdb/*`; baken `pdb/*.rs`; fragmede FORMAT.md; seabass `pdb_row_writer.cpp`; fourfour §3–6.
All [RB] statements were re-checked on: rekordcrate `complete_export/empty` (rb6, empty),
`complete_export/demo_tracks` (rb6, edited), `pdb/num_rows` (rb6, 3886 tracks), seabass
`pdb_playlist_tree/0-base.pdb` (rb 7.2.18, 34 tracks), seabass `anonymized_library` (rb7, 1161 tracks).

### 2.1 Global structure

* File = array of pages, `len_page` = **4096** (every observed file). Page *i* starts at `i*4096`.
* Page 0 = file header. Every table is a linked list of pages; its first page is an **index page**
  (flags 0x64, no rows); rows live in **data pages** (flags 0x24/0x34).
* rekordbox's file may end before `next_unused_page` (pages are extended lazily) [RB]; a writer may
  instead write explicit zero pages (baken does) [HW]. Either way file size is a multiple of 4096.
* Page index values must be < 0x03FFFFFF (0x03FFFFFF is the "no page" sentinel; rekordcrate).

### 2.2 File header (page 0)

| Off | Size | Field | Value to write |
|---|---|---|---|
| 0x00 | u32 | magic | 0 |
| 0x04 | u32 | len_page | 4096 |
| 0x08 | u32 | num_tables | 20 (export.pdb), 9 (exportExt.pdb) |
| 0x0C | u32 | next_unused_page | one past the highest page index used **anywhere, including every empty_candidate** |
| 0x10 | u32 | unknown | 5 in the rb6 files and a long-lived rb7 stick, 4 in the fresh rb 7.2.18 export [RB]; fragmede saw 1 in small exports; baken writes 1 [HW]. Not validated by players. (fourfour's "must be 5" is refuted by baken #115.) |
| 0x14 | u32 | sequence | **> every page's sequence** (write max+1). CDJ-3000 rejects otherwise (fourfour bisection [HW]). |
| 0x18 | u32 | gap | 0 (possibly high half of a 64-bit sequence) |
| 0x1C | 16×num_tables | table directory | see below |
| rest | | | zero [RB] |

Table directory entry (16 bytes):

| Off | Size | Field |
|---|---|---|
| 0x0 | u32 | type (table id, enum below) |
| 0x4 | u32 | empty_candidate: page the table will grow into next. Must be a zero page or lie beyond EOF. **`last_page.next_page == empty_candidate`** for every table [RB, fragmede]. |
| 0x8 | u32 | first_page: the table's index page |
| 0xC | u32 | last_page: last data page, or the index page itself when the table has no data |

Write the 20 entries in type order 0..19 [RB]. Every table must be present even when empty, each
with its own index page.

Table types (export.pdb):

| Type | Name | Rows written in a fresh export |
|---|---|---|
| 0x00 | tracks | yes |
| 0x01 | genres | if used |
| 0x02 | artists | if used (also composers, remixers, original artists) |
| 0x03 | albums | if used |
| 0x04 | labels | if used |
| 0x05 | keys | if used |
| 0x06 | colors | **always 8 rows** |
| 0x07 | playlist_tree | if any playlist |
| 0x08 | playlist_entries | if any playlist |
| 0x09, 0x0A | unknown | never (index page only) |
| 0x0B | history_playlists | no (written by players) |
| 0x0C | history_entries | no (written by players) |
| 0x0D | artwork | if artwork |
| 0x0E, 0x0F | unknown | never |
| 0x10 | columns | **always 27 rows** |
| 0x11 | menu / category ("unknown_17") | **always 22 rows** |
| 0x12 | sort ("unknown_18") | **always 17 rows** |
| 0x13 | history (sync/property row) | **always ≥1 row** |

**Naming conflict (important):** Deep Symmetry's exports.html table lists `11 history_playlists`,
`12 history_entries` in its hex column; the Kaitai spec, rekordcrate, baken and every real file say
**0x0B/0x0C** are the history tables and 0x11/0x12 are menu/sort configuration. fourfour followed the
doc table, labelled 0x11/0x12 "history", and concluded "empty history tables cause *database not
found*" on the CDJ-3000. Resolution: the tables that must be populated are **0x11, 0x12 and 0x13**;
empty 0x0B/0x0C are fine (baken writes them empty and passed on CDJ-3000 and NXS2 [HW]).
Which of 0x11/0x12/0x13 the CDJ strictly needs individually is **UNCERTAIN**; write all three as
rekordbox does.

### 2.3 Common page header (all pages, 0x00–0x1F)

| Off | Size | Field | Notes |
|---|---|---|---|
| 0x00 | u32 | 0 | |
| 0x04 | u32 | page_index | = own index |
| 0x08 | u32 | type | table type |
| 0x0C | u32 | next_page | next page of this table; the last page points at the table's empty_candidate |
| 0x10 | u32 | sequence | see 2.8 |
| 0x14 | u32 | 0 | |
| 0x18 | 3 bytes | packed row counts | see below |
| 0x1B | u8 | page_flags | 0x24 data, 0x34 data with deleted rows, 0x64 index |
| 0x1C | u16 | free_size | data pages: see 2.5; index pages 0 |
| 0x1E | u16 | used_size | data pages: heap bytes used; index pages 0 |

Packed row counts (Robin McCorkell's decoding, Deep Symmetry/rekordcrate): bytes 0x18..0x1A read as
a 24-bit little-endian integer `v`:

* bits 0–12 `num_row_offsets` (n): row slots ever allocated in the page (incl. deleted).
* bits 13–23 `num_rows` (valid): rows currently present.

```c
p[0x18] = n & 0xFF;
p[0x19] = ((n >> 8) & 0x1F) | ((valid & 0x7) << 5);
p[0x1A] = (valid >> 3) & 0xFF;
```

Limits: n ≤ 8191, valid ≤ 2047 per page. In a fresh export `valid == n`.
Do **not** use the old Kaitai `num_rows_small`/`num_rows_large` heuristic (fragmede shows it drops
rows); the field at 0x22 is not a row count (see 2.5).

page_flags bits (Deep Symmetry): bit 6 = index page, bit 4 = page contains deleted rows, bits 5
and 2 always set, others 0. rex also accepted 0x10/0x37/0x44 when reading; never write those.

### 2.4 Index page (first page of every table)

Byte-exact layout of a fresh index page [RB] (rekordcrate `IndexPageHeader`, baken `index_page`):

| Off | Size | Value | Meaning |
|---|---|---|---|
| 0x00–0x1F | | common header | page_flags 0x64, row counts 0, free 0, used 0, **sequence 1** in a fresh export |
| 0x0C | u32 | first data page, or the empty_candidate if the table has no data | header next_page |
| 0x20 | u16 | 0x1FFF | unknown_a |
| 0x22 | u16 | 0x1FFF | unknown_b |
| 0x24 | u16 | 0x03EC | = 1004, entry capacity |
| 0x26 | u16 | 0 | next_offset (entries in use) |
| 0x28 | u32 | own page index | |
| 0x2C | u32 | first data page, or **0x03FFFFFF** when the table has no data | |
| 0x30 | u32 | 0x03FFFFFF | |
| 0x34 | u32 | 0 | |
| 0x38 | u16 | 0 | num_entries |
| 0x3A | u16 | 0x1FFF | first_empty (none) |
| 0x3C | 1004×u32 | 0x1FFFFFF8 each | empty entry slots (0x3C + 4016 = 0xFEC) |
| 0xFEC | 20 bytes | 0 | |

Non-empty entries are `(page_index << 3) | flags(3 bits)` and list data pages that contain
**deleted** rows (a free-space list; seabass, acrilique gist, rekordcrate). A from-scratch writer
writes none. fourfour's "tracks/history index pages need `0x1FFF0001`, `0x10`/`0x140` and
unknown7=1" are exactly such deletion entries (`0x10>>3` = page 2, `0x140>>3` = page 40) copied from
an incrementally edited reference export; they are **not** required — baken writes empty index
pages and passed on CDJ-3000 and NXS2 [HW]. (In rekordbox files with deletions, 0x20/0x22 may hold
other values, e.g. 0x0001/0x0001 or 0x0002/0x00B3 [RB].)

### 2.5 Data page

```
0x00-0x1F  common header (flags 0x24)
0x20 u16   transaction_row_count
0x22 u16   transaction_row_index
0x24 u16   0
0x26 u16   0
0x28 ...   heap: rows, growing upward; row offsets are relative to 0x28
...        free space
end        row index groups, growing downward from 0x1000
```

**Row index groups** (Kaitai `row_group`): group g (0-based) has `base = 4096 - 0x24*g`.

| Position | Size | Field |
|---|---|---|
| base − 2 | u16 | transaction flags: bit s = slot s touched by the page's last transaction |
| base − 4 | u16 | presence flags: bit s = slot s is a live row |
| base − 6 − 2·s | u16 | heap offset of slot s (s = 0..15), relative to 0x28 |

A full group is 36 bytes. The **last, partial group stores only its used slots**: it occupies
`2*(n%16) + 4` bytes (offsets beyond the last slot are not reserved). Hence:

```c
dir_bytes = 2*n + 4*ceil(n/16.0);          /* n = num_row_offsets */
used_size = sum over rows of alloc(row);    /* every alloc is a multiple of 4 */
free_size = 4096 - 0x28 - used_size - dir_bytes;
```

(verified on 202/202 data pages by fragmede and by baken's 284-row test page: used 3408, free 8.)
A row fits if `used + align4(len) + dir_bytes(n+1) <= 4096 - 0x28`.

Rows are appended in slot order; offsets are multiples of 4 and strictly ascending; slot 0 at heap
offset 0 [RB]. Bytes between a row's content and the next row are zero.

**Transaction fields** (seabass, Deep Symmetry; values [RB] in fresh exports):

| Table kind | 0x20 tran_rc | 0x22 tran_ri | transaction flags |
|---|---|---|---|
| rows added one at a time (tracks, artists, albums, genres, labels, keys, playlist tree/entries, artwork, history 0x13) | 1 | n−1 | only the last slot's bit (in the last group); all other groups 0 |
| written in one transaction: colors 0x06, columns 0x10, menu 0x11, sort 0x12 | n | 0 | all present bits |
| last transaction failed (seen in edited files) | 0x1FFF | 0x1FFF | 0 |

baken writes `(1, n−1)` for 0x11/0x12 too and sets transaction flags = presence flags on every
page; that passed on CDJ-3000 and NXS2 [HW], so players evidently do not validate these. fourfour
claims the columns page "uses a completely different header" and that getting it wrong gives
*database not found* — that "different header" is just the `(n, 0)` single-transaction style.
Copy rekordbox and the question is moot.

fragmede describes 0x22 as "slot count at the page's previous write"; for fresh pages that equals
n−1 / 0 as above, so all descriptions agree for a writer.

### 2.6 Row allocation sizes (slack)

rekordbox allocates more heap than a row's content; reproducing it matters (see gotcha G6).
Verified [RB] on every row of the rb6 demo tracks page (7/7 tracks) and by baken/fragmede on rb7:

| Row | alloc (bytes) |
|---|---|
| track | `0x88 + Σ align4(len(sᵢ)) over the 21 strings + 4` (minimum 224) |
| artist | `12 + align4(len(name)) + 4` |
| album | `24 + align4(len(name)) + 4` |
| tag (exportExt) | `32 + align4(len(name)) + align4(len(second string)) + 4` |
| exportExt table 7 row | 60 |
| history 0x13 | `36 + align4(len(label))` (40 with empty label, 48 with an 11-char label) |
| genre, label, artwork, history_playlist, column | `align4(4 + len(string))` |
| key, color | `align4(8 + len(string))` |
| playlist_tree | `align4(20 + len(name))` |
| playlist_entry, history_entry | 12 |
| menu 0x11, sort 0x12 | 8 |

`len(s)` is the full encoded DeviceSQL string length (header included). General rule for rows with a
string-offset array: `align4(fixed part incl. offsets) + Σ align4(strings) + 4`.

### 2.7 Chains, empty candidates, next_unused_page

Invariants a writer must keep (all sources agree; baken layout [HW]):

1. `table.first_page` = index page; index header `next_page` = first data page (or the
   empty_candidate when no data); index body `0x2C` = first data page (or 0x03FFFFFF).
2. Data pages chained via `next_page`; the **last** data page's `next_page` = `table.empty_candidate`.
3. `table.last_page` = last data page (index page if none).
4. Each table has its **own** empty_candidate page: all-zero or beyond EOF, not used by anything else.
5. `header.next_unused_page` > every page index above, including all empty_candidates.
6. Data pages hold only rows of their table; tables never share pages.

Players write history into the file (tables 0x0B/0x0C/0x13) and back it up as `export.pdb.bak`,
so allocation metadata must be valid for the player's own DeviceSQL engine, not just for reading.

Two working layouts:

* **baken (hardware-verified)**: page 0; then for each table 0..19: its index page immediately
  followed by its data pages; then 20 zero pages, one empty_candidate per table;
  `next_unused_page` = total page count.
* **rekordbox fresh export** [RB, rb6 empty]: index page of table t at `1+2t`, page `2+2t` = its
  first data page (or a zero page reserved as its empty_candidate); further data pages and the
  candidates of non-empty tables are allocated after page 40 (often beyond EOF). In an empty rb6
  export: 41 pages on disk, `next_unused_page` 46.

### 2.8 Sequence numbers

Each page's `sequence` (0x10) is stamped with the database sequence at the time the page was
written; the header's `sequence` is the *next* value, so it must exceed every page's value
(Deep Symmetry). Values in fresh exports [RB]: all index pages 1; colors 2; columns 3; menu 0x11 4;
sort 0x12 5; other data pages larger, increasing in write order (rb6 empty: header 9; oddly its
0x13 data page carried sequence 1).
baken: index 1, colors 2, columns 3, everything else from 11 upward, header = max+1 [HW].
fourfour's "base + (rows−1)*5" formulas are incidental to their reference export; only
**header > max(page)** is known to be checked (CDJ-3000, fourfour [HW]).

### 2.9 DeviceSQL strings

| First byte | Form | Layout |
|---|---|---|
| odd | short ASCII | `b = ((len+1) << 1) | 1`; `len` = text bytes ≤ **126**; text follows; no terminator. Empty string = `0x03`. |
| 0x40 | long ASCII | `0x40, u16 total_len, 0x00, text`; total_len = text bytes + 4 |
| 0x90 | long UTF-16LE | `0x90, u16 total_len, 0x00, UTF-16LE units`; total_len = 2·units + 4; no terminator |
| 0x90 + 0x03 | ISRC (track string 0 only) | `0x90, u16 total_len, 0x00, 0x03, ASCII ISRC, 0x00`; total_len = len+6 (e.g. 12-char ISRC → `90 12 00 00 03 … 00`) |

Encoding choice as rekordbox makes it [RB]: pure ASCII ≤ 126 bytes → short; pure ASCII > 126 →
**0x40**; any non-ASCII → 0x90 (no short Unicode form). Verified: rekordbox 7 files contain 0x40
strings (file paths, comments > 126 chars) and 0x90 strings.
baken never emits 0x40 (it encodes long ASCII as 0x90) and states rekordbox 7 never wrote 0x40 in
its reference — **UNCERTAIN/conflict**; the 0x40 form demonstrably occurs in real rb7 exports
(22 strings in the seabass rb7 fixture, 50 in rekordcrate's rb6 library), so players must read
both. Either choice decodes; matching rekordbox (0x40) is the conservative choice.
Text is UTF-16 *code units* (surrogate pairs allowed; baken round-trips "🅴").

**Alignment rule (hardware-critical):** every long string (0x40 and 0x90, incl. ISRC) starts on a
**4-byte boundary relative to the row start** (rows themselves start 4-aligned in the heap, so this
is also page-aligned). Short ASCII strings are packed with no padding. Padding bytes are 0.
[RB] 1275/1275 long strings in rekordcrate's library, 167/167 in the seabass rb7 fixture.
[HW] Unaligned UTF-16 strings froze a CDJ-2000NXS2 (fw 1.87) drawing the ARTIST list (baken #168)
and instantly crashed CDJ-350s (rekordcrate PR #250). Tables whose string sits at a fixed offset
(genre +4, key/color +8, playlist +20, column +4, artwork +4, history_playlist +4) are aligned
automatically; tracks, artists, albums and the 0x13 row need explicit padding.

### 2.10 String-offset arrays and `subtype`

Rows with variable strings referenced by offset (tracks, artists, albums, exportExt tags) carry an
offset array preceded by the magic 3 (rekordcrate `OffsetArray`): `u8 0x03` + u8 offsets, or
`u16 0x0003` + u16 offsets. Bit 0x04 of the row's `subtype` selects u16 offsets. Offsets are
relative to the row start. Artists use 0x0060 (u8) / 0x0064 (u16 "far"), albums 0x0080/0x0084,
tags 0x0680/0x0684, tracks 0x0024 (always u16).

rekordbox never used the far forms in any file checked (3300+ artist and album rows) [RB];
**always write 0x0060/0x0080** with the name directly after the header.

`index_shift` (u16 at +2 in tracks, artists, albums, tags, 0x13 rows) = **0x20 × slot index within
its page** (counts deleted slots, restarts at 0 on each page) [RB].

### 2.12 Writer recipe (from scratch)

1. Collect tracks (ids 1..N), artists (incl. composers, remixers, original artists), albums,
   genres, labels, keys (used only), artwork, playlists (+ ancestor folders), entries.
2. Encode each row with its final slot index known (index_shift depends on it).
3. Fill pages per table in type order: append while `used + align4(len) + dir_bytes(n+1) <= 4056`.
4. Assign page numbers (baken layout is simplest), one zero empty_candidate per table,
   `next_unused_page` = page count.
5. Write data pages: header (2.3, 2.5), transaction fields (2.5 table), row groups, rows.
6. Write index pages (2.4) once first data pages are known.
7. Sequences: index 1, colors 2, columns 3, menu 4, sort 5, others ≥ 6 ascending; header = max+1.
8. Page 0 (2.2). Write the file atomically (temp + rename) — players and rekordbox both read it.
9. Remove stale OneLibrary/exportExt files (1.1).
10. Self-check before shipping: re-parse with an independent reader (rekordcrate or the Kaitai
    spec) and assert: chains end at `last_page` whose `next_page` = empty_candidate; popcount of
    presence flags = `num_rows`; `free_size` formula holds on every data page; every long string
    offset ≡ 0 mod 4; header sequence > every page sequence.

C structs (packed, little-endian host assumed; otherwise serialise field by field):

```c
struct pdb_file_header {          /* page 0 */
    uint32_t magic;               /* 0 */
    uint32_t len_page;            /* 4096 */
    uint32_t num_tables;          /* 20 */
    uint32_t next_unused_page;
    uint32_t unknown;             /* 1, 4 or 5 */
    uint32_t sequence;            /* > max page sequence */
    uint32_t gap;                 /* 0 */
    struct { uint32_t type, empty_candidate, first_page, last_page; } tables[20];
};

struct pdb_page_header {          /* 0x00..0x27 */
    uint32_t zero;
    uint32_t page_index;
    uint32_t type;
    uint32_t next_page;
    uint32_t sequence;
    uint32_t zero2;
    uint8_t  row_counts[3];       /* 13-bit num_row_offsets | 11-bit num_rows << 13 */
    uint8_t  page_flags;          /* 0x24 data, 0x64 index */
    uint16_t free_size;
    uint16_t used_size;
    uint16_t w20;                 /* data: tran_row_count; index: 0x1FFF */
    uint16_t w22;                 /* data: tran_row_index; index: 0x1FFF */
    uint16_t w24;                 /* data: 0; index: 0x03EC */
    uint16_t w26;                 /* data: 0; index: next_offset (0) */
};
```

| 0x03 | tags (My Tag categories and tags) — 28 default rows |
| 0x04 | tag_tracks (Kaitai, rekordcrate, Deep Symmetry). fragmede guesses type 8 instead — UNCERTAIN, trust 4 (derived from data with tagged tracks) |
| 0x05, 0x06 | unknown, empty |
| 0x07 | one unknown row (below) |
| 0x08 | unknown, empty |

Tag row (type 0x03):

```
0x00 u16 0x0680 subtype (0x0684 = u16 offsets, never seen)
0x02 u16 index_shift (0x20 × slot)
0x04 u32 0
0x08 u32 0
0x0C u32 category id (0 for a category row)
0x10 u32 position (0-based within category, or category position)
0x14 u32 id   (categories 1..4; tags: persistent random 32-bit values)
0x18 u32 is_category: bytes 00 00 00 01 for a category (u32 0x01000000), 0 for a tag
0x1C u8  0x03
0x1D u8  ofs_name (0x1F)
0x1E u8  ofs_unknown (offset of a second, always-empty string after the name)
0x1F     name, then 0x03
```
alloc `32 + align4(len(name)) + 4 + 4`. Default set [RB]: categories Genre(1), Components(2),
Situation(3), "Untitled Column"(4) with tags Acid House, Deep House, Techno, Nu Disco, Electro
House, Bass Music, Trap / Synth, Vocal, Beat, Sub Bass, Percussion, Piano, Dark, Upper /
Main Floor, Second Floor, Lounge, Mid Night, Morning, Build up, Peak Time, Build down / My Comment.
Tag ids are user/library specific (identical in two exports from the same install). Full bytes in
Appendix B. Page is written in one transaction (tran_rc = 28, tran_ri = 0).

Tag-track row (type 0x04): `u32 0; u32 track_id; u32 tag_id; u32 3` (16 bytes).

Type 0x07 row [RB] (60 bytes): `0007 0000`, 20 zero bytes (0x04–0x17), `u32` at 0x18
(0x05E7FA81 in the rb6 files — the track-row constant at 0x18 of that database was 0x05E7FA80,
i.e. +1; UNCERTAIN meaning, perhaps OneLibrary `property.myTagMasterDBID`), `03`, five u8 offsets
`22 23 24 25 26`, five empty strings `03 03 03 03 03`, zero pad.

## 4. Gotchas (numbered; evidence; licence of the source)

| # | Gotcha | Evidence |
|---|---|---|
| G1 | **Long strings (0x90 UTF-16, also 0x40) must start 4-byte aligned in the row.** Unaligned UTF-16 froze a CDJ-2000NXS2 on the ARTIST preview; ASCII-only sticks were fine. CDJ-350s crashed instantly. | baken #168/d79a235 [HW, MIT]; rekordcrate PR #250 [HW, MPL]; [RB] 100% of long strings aligned |
| G2 | History 0x13 row `num_tracks` must be the track count; 0 → CDJ-3000 "Songs 0". | baken #168 [HW] |
| G3 | Header `sequence` must exceed every page's sequence, else CDJ-3000 "rekordbox database not found". | fourfour bisection, CDJ-3000 fw 3.19 [HW] |

| G5 | Any invalid page → "rekordbox database not found"; there is no partial failure. Debug by page-swapping with a known-good rekordbox export (bisection). | fourfour §7–8 [HW] |
